8. CORRECTNESS CONSTRAINTS THAT MUST SURVIVE OPTIMIZATION

- Critical GPU-writable host import:0x1120000000+0xac600000 (~2758MiB).
  It must remain coherent. Blindly unpinning it, substituting a stale CPU copy
  or making it read-only can corrupt dynamic GPU writes.
- Before/after writeback snapshots preserve the pre-work GPU baseline while
  respecting concurrent CPU updates. Reading guest RAM as the original baseline
  is not equivalent. GPU ordering and lifetime fences must remain correct.
- A hash is not an exact dirty-byte proof. If using block fingerprints, collisions
  must not silently lose writes; exact comparison or equivalent proof is needed.
- Imports can outlive cache removal because pending GPU work holds references.
  Retirement must defer destruction until completion. Removing a map entry is
  not evidence that physical pages have immediately become unpinned.
- SourceVersion/cache identity must reflect compiler changes. Do not forge the
  old key or use stale generated shaders merely to keep the cache warm.
- GPU pipeline cache bytes are device/driver specific. Preserve metadata and
  back up before replacement. Do not overwrite a live process's cache.
- APS5_DUMP_PIPELINE_DIR is a diagnostic skip/stop route, not a benchmark route.
  APS5_TRACE_PIPELINE_DIR captures inputs while continuing required work.
- Do not remove RAM/commit/disk guards to conceal an unresolved memory problem.
- Do not disable protection, pagefile, fan control or unrelated Windows services
  as a substitute for fixing emulator behavior. No further debloating is part of
  this handover. Avoid killing unknown Codex/Claude/helper processes by name.
